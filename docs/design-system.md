# Design system

Source of truth: [`frontend/src/styles/tokens.css`](../frontend/src/styles/tokens.css). Tailwind classes map to tokens in `frontend/src/styles/index.css`.

## Rules

- Square everything (radius 0, including Mapbox UI). Exception: round data marks on the map.
- No circular spinners for running work (use a thin progress line); no radio circles (use segmented controls). Exception: data loading from the backend uses the one `Loader` (`components/Loader.jsx`, `.loader`: outer ring `--text`, inner ring #ff3d00, counter-rotating) — on the map centred over a 0.5 px blur without tint, none before the map has drawn (`MapLoader`, first load of a switched-on live layer), elsewhere without backdrop (`LoaderBlock` in the attribute table and cards, 14 px in a layer row).
- Text that may truncate (layer names) uses `OverflowText`: ellipsis, and the full text in a tooltip below it only when cut off.
- Destructive actions (delete, discard) always confirm in `ConfirmDialog` (native modal `<dialog>`, Cancel focused first, Esc/backdrop cancel, solid `--destructive` red button); a delete trigger button uses the same solid red.
- Font: Urbanist; body 13px (`--fs-sm`); numbers in tables use `tabular-nums`.
- Sizing: rem only, so the root font size per screen class (`index.css`) scales the whole UI; px figures in these docs are at the 16 px desktop base. Write new arbitrary sizes in rem (`h-[1.875rem]`, not `h-[30px]`); icons keep `size={15}` (CSS restates it in rem). px only for hairlines (borders, focus ring, scrollbar, resize-handle offsets), map content and A4 report pages (paper: `components/report` page files and `LegendSwatch paper`). Charts drawn from a measured px width use `useRootScale` / `rem()` (`lib/useRootScale.js`) or a `viewBox` with `w-full`.
- Themes: `data-theme="dark|light"` on `<html>`; every component must work in both.
- Scrollbars: global only (`index.css`), no end arrows, `--scrollbar-w` wide, faint `--scrollbar-thumb`; no per-component scrollbar styles.
- Alignment rule (universal, `index.css` "ALIGNMENT RULE"): in every row (buttons, links, chips, tabs, menu items, options, inputs with icons, list rows) icons and text share one horizontal centre line: the icon box centre = the centre of the text's cap band (baseline to cap height), for mixed case and caps alike, at every size. How: (1) controls that are flex/grid rows centre their items by default; (2) a childless `span`/`a`/`label`/`time` in a centring row (or a text-only button) is trimmed to its cap band, so text goes in its own `<span>` — never a bare text node or `{expr}` beside an icon; (3) icons are block boxes that never shrink; (4) `truncate`/`overflow-hidden` labels clip sideways only (unlayered rule), so descenders survive and the trim holds; (5) icon beside multi-line text (row `items-start`): text block `text-cap-start`, icon wrapped in `<span className="icon-cap">` carrying the first line's text size. (6) list rows with two text lines and trailing meta (status chip, value) are one grid, `grid-cols-[auto_minmax(0,1fr)_auto] items-center`: each line and its meta share a grid row (title ↔ chip, subtitle ↔ value), the mark spans the rows — never two independently stacked columns. Chips are part of the rule (`level-chip`: cap-trimmed text, equal padding). Never nudge icons or labels with margins, padding or offsets (`mt-px`, `mt-0.5`, `top-[1px]`); an absolutely positioned icon centres with `top-1/2 -translate-y-1/2`. Browser note: the trim needs `text-box` (Chrome 133+, Safari 18.2+); Firefox falls back to the font's line box (close, not exact). Native input text cannot be trimmed, so search and filter boxes use `SearchBar` (built on `SearchField`): the input text is transparent and both value and placeholder are drawn by a trimmed overlay span that follows the input scroll; never a bare `<input>` next to an icon. Vertical labels: never `writing-mode` text beside an icon (it cannot be trimmed); rotate a cap-trimmed horizontal span 90° centred in a slot sized by an invisible sideways copy (see the collapsed right-panel strip in `App.jsx`).
- Dropdowns, menus and scrollable lists: no top or bottom padding on the list container (rows run edge to edge); rows are single-line, `text-xs`, 28px (`h-7`) for text rows; thumbnail rows use a 25px thumbnail (`size-6.25`) with 2px vertical padding and take their height from it; no secondary description; the selected row is shown by `bg-accent-soft`, not an extra mark.
- Panel notes (caveats, disclaimers, method notes): never a strip inside the panel; pass the text as `info` to `PanelHeader`, which shows an ⓘ button left of the header actions with the note on hover or keyboard focus. Current: Ranking → scenario-effects disclaimer.
- Map nav-control panels: always `ControlPopover`, opened by `MapControls` (one at a time; outside click, Esc, its control button or folding the column closes it; choosing an item inside never closes it). They open from the top of the control column, left of the controls, and may use the full map height. Motion: unroll downward from the top edge with a slight drift in from the right, rows staggered via `popoverRowStyle`; quicker roll-up on close.
- Search: every table and list gets the one `SearchBar` (`components/SearchBar.jsx`; size `sm`/`md`, variant `field`/`floating`, Esc clears) with `useSearch` (`lib/search.js`): any-column, case-insensitive; counts and exports follow the filtered rows. Dock tabs put it in the dock bar; panel tables put it above the table, inside the `ExpandSlot` so it follows into the focus view; the query lives in the store so it survives expand. No-match and empty states use `SearchEmpty`, centred in the space under the table header. Never a bespoke search input. Long dropdowns pass `searchable` to `Select` for the same bar above their options.
- Info notes (ⓘ popups): text justified with automatic hyphenation (`PanelInfo`, `components/SidePanel.jsx`); every panel note uses it.
- Report pages (`components/report`): A4 at 96 dpi (794 × 1123 px), `--report-page` white with light tokens in both themes; header (mark, brand, report title) and footer (data version, generation date, page x of y, licence line) on every content page; tables and the chart follow the dataviz rules (one hue per series, 90 % whiskers, values direct-labelled). Print tables are not sortable or searchable (paper).
- Exports: every file export (CSV, JSON, PNG, DOCX) goes through `saveFile` (`lib/saveFile.js`): a save dialog for folder and name first (Chromium), a normal download elsewhere; never a direct `<a download>`. PDFs use the print dialog ("Save as PDF" asks where), printed with `@page { margin: 0 }` and page padding, so the browser adds no date or URL lines.
- Printed text (report pages, PDFs, DOCX): Urbanist, light-theme colours (`resolveLight` in `lib/css.js`), running text justified with hyphenation (tables, headings and captions are not); English headings, table heads and figure titles in Title Case (user-entered text and German stay as written).
- Rich text (report Summary, Appendix): `RichTextEditor` (bold, italic, underline, text colour and highlight via `ColorPicker`, bullet and numbered lists, clear formatting) writing a cleaned HTML subset (`lib/richText.js`) that pages and DOCX both read.
- Keyboard shortcuts: one registry (`lib/shortcuts.js`) drives the key handler and the Settings list; single keys without Ctrl/Alt/Cmd, never while typing. A new panel, view or tool adds its entry there.
- Public Heat Portal (`components/portal`): touch targets ≥ 44 px (`h-11`/`size-11`; exception by request: the map controls use the shared compact 28 px `MapButtons`), body text ≥ 14 px and inputs 16 px (no zoom on phones), plain-language sentences, every colour paired with words or an icon, an `aria-live` sentence for each new result, skip link to the panel; same tokens, square shapes and both themes as the workspace.
- Dates: `DatePicker` (`components/DatePicker.jsx`; themed calendar, month and year views from the header title, Clear / Today), never a native `<input type="date">`.
- Tables: every table is sortable — `useSort` (`lib/useSort.js`) + `SortTh` headers, click cycles descending → ascending → original; keep the sort state outside the table (store) when it can move into the expanded view.
- Expand: every compact table or chart (dock tabs, panel tables, panel charts) has an `ExpandButton` in its header and its body in an `ExpandSlot` with the same id; expanded, it covers the map container edge to edge (no inset; the overlay header ends in a restore button (`FiMinimize`); the placeholder RESTORE, that button or Esc restores, one at a time). While expanded the element's own `ExpandButton` is hidden (an empty cell keeps the header height; the dock bar drops it) and its original place keeps its exact height with one bold uppercase text control, IN FOCUS, that crossfades to an orange RESTORE on hover or focus and restores on click (no icon, no separate button). Dock tabs: the focused tab stays in focus view while other tabs are browsed in the dock; expanding another tab swaps them. The dock draws the focused tab from one stable `overlayOnly` slot and the active tab from a `placeholderOnly` slot, so tab switches never remount (flicker) the overlay. Charts draw at a larger internal size when `large` so text keeps its size.
- Tables: classification labels (risk, level) use the `level-chip` utility (tinted bg + coloured text); numbers stay plain coloured text. Every chip has one width (`--level-chip-w`; icon-only chips `--chip-compact-w`) with its content centred; a chip with an icon or pips centres icon and text together as one group.
- Focus ring: keyboard only (`data-input` on `<html>`); a mouse click never leaves an outline.
- Layout: top nav · left rail + panel · map (flex) + bottom dock · right panel. Sizes from tokens (`--nav-h`, `--panel-w` (both sides), `--dock-*`). Map calls `resize()` via ResizeObserver. Every right-panel view collapses with `VscCollapseAll` in its header actions.
- Layers panel row actions: no hover background; hovering turns the icon accent (a preview of its active state), pressed/on keeps it accent.
- Layers panel rows: geometry icon (hover or focus shows a tooltip with the layer kind and size, e.g. "Polygon layer · 2,948 features") · name · actions (attribute table, zoom to layer, symbology `LiaPaletteSolid`, visibility switch (the `RiToggleFill`/`RiToggleLine` shape drawn as one animated SVG: the pill fills and the knob slides, 200 ms)) · the layer's legend (`LayerLegend`, from its style; every symbol and colour bar has a thin `--border-strong` outline outside it so light or dark data colours stay visible in both themes; more than 6 classes fold behind "+N more"). Rasters have no table button.
- Feature popup (`FeaturePopup`, content per layer in `lib/popups.js`): one popup for the one clicked feature (topmost: points before lines before areas, admin units last), no paging, no side stripe. Drawn at 75 % (`--popup-scale` on `.hs-popup`, CSS zoom on card and tip; every size below is before scaling). Card on `--surface-strong` with a `--border-strong` frame and an attached tip (12 px square in the card colour turned 45°, half inside the card, bordered on its two outer sides, ending ~4 px short of the clicked spot or of a point's ring): header (small square in the feature's map colour + layer caps label + close, title, subtitle, `popup-chip` chips), a key-value band on `--field` (up to 3 divided columns, large values coloured by meaning: heat levels, sealing / vulnerability ramps, status), attribute rows (label left, value right), footer actions Zoom to · Show in table. While open, the feature is highlighted on the map in `--feature-highlight` (yellow, both themes) on its exact geometry: fill 22 % + 3 px outline (areas), 3 px line, 11 px ring (points), or its whole solid in 3D. Opens with a pop (scale 0.6 → 1 with overshoot from the tip, 300 ms; fade under reduced motion); × or Esc closes.
- Dock tab counts (Jobs History): small solid boxes with a white count, one per status present: running `--level-high` (orange), done `--success` (green), failed `--danger` (red); the status in the tooltip. The dock bar keeps the tabs whole: the tab actions give way first (the filter box shrinks to 80 px).
- Attribute table columns: fixed widths, no wrapping (ellipsis, full value as a hover title); Excel-style handle on each header's right edge (`col-resize` cursor, 1 px line turning 2 px accent on hover): drag to resize (min 48 px), double-click to fit the longest value and the header; the table scrolls sideways when wider than the dock. Toolbar icon buttons (28 px, accent when on): Export CSV (`BsFiletypeCsv`, accent; the Summary tab uses `BsFiletypeCsv` and `BsFiletypePdf` the same way), Columns (`LuColumns3`; a small accent mark when columns are hidden) opens a menu in a fixed layer, below the button or above it when there is no room, never past the window, with a checkbox per column (the last visible one cannot be hidden), Show all, Reset widths. Widths and hidden columns are saved per layer (`hs-table-columns`); CSV export holds the visible columns.
- Attribute table: a 24 px full-width strip above the header names the layer shown (centred caps, `--accent` on `--accent-soft`, accent-line bottom border); it stays put while the table scrolls.
- Attribute table, vector layers: a row click highlights its feature in `--feature-highlight` on the map (whole solid in 3D) and in the row (22 % yellow tint + 2 px yellow inner edge); clicking the row again, or Esc, clears it. A click never moves the map. Icon toggle "Fly to features" (`LuLocateFixed`, pressed = accent, saved): on, a double-click flies to the feature (points to street level, others fit); off, rows never move the map.
- Map readout (top nav, GIS view, ≥ xl): mono tabular "Zoom 12.34 | Cursor 49.48750° N, 8.46600° E" (map centre when the pointer is off the map); click copies "lat, lon". Address search: typed or pasted coordinates ("49.48, 8.46", "8.46 49.48", N/S/E/W, "49,48; 8,46") show "Go to …" first; the chip at the end of the box ("Lat, Lon" ↔ "Lon, Lat", accent when the text is coordinates, saved) sets the order when no hemisphere letters decide it.
- Layer order (`LayerOrderPanel`): header button `HiSortAscending` (right of the hide/show-all eye in the Layers panel) toggles an overlay on the map under the address search (w-56): title, filter, then only the layers shown on the map, top of the list = drawn on top. A row is drag handle · 10 px round dot from the layer's symbology (solid single colour, diagonal gradient for ramps, equal slices for classes; outline colour for outline-only areas) · name. Drag rows (accent drop line, dragged row faded) or Alt+↑/↓; the map restacks at once (symbology `order`). Expands/collapses with grid-rows 0fr↔1fr, fade and 8 px rise (300 ms, ease-out-expo); Esc or × closes.
- Symbology (right view `symbology`): layer picker, tabs Style (renderers incl. rule-based) · Label (text from field or expression, font, halo, background box, placement per geometry, rendering, label classes) · Query (definition or selection; condition builder (values from a sorted list of the field's distinct values with search: one value = radio list that also takes typed text, IN / NOT IN = checkbox list written as `IN ('a', 2)`, BETWEEN = from/to) ↔ SQL editor `SqlField` with live validation; apply, "Clear all" (removes every condition and the applied query), × on a condition re-applies at once while a query is applied, zoom, show in table, saved queries; an active query shows a filter mark on the layer row), 3D ("Show this layer in 3D" replaces the 2D drawing with fill-extrusions: polygons raised, points as square/circle/hex columns, lines as walls (inside polygon rings), raster cells as columns, the DEM as terrain; height from a field or cell value mapped linearly or by square root onto lowest–highest metres, or fixed; colour from the Style tab or single; turning it on tilts a flat map), collapsible `Section`s of compact controls from `components/controls.jsx` (`Select`, `Field`, `Slider`, `NumberField`, `ColorField`, `Check`, `Segmented`). Class lists toggle visibility with an eye in a 28 px bordered cell (crossed eye + faded row when hidden), not a checkbox; the compact `ColorField` swatch is 28 px too. Labelled options use `Checkbox size="md"` (20 px). Colours are always picked with `ColorField` → `ColorPicker` (saturation/value square, hue and opacity bars, hex + opacity, eyedropper, 3 preset rows incl. transparent and black); never the native colour input. New styleable layers are added to `lib/layers.js` and get a default in `lib/styleModel.js`; never style a data layer inline in `MapView`.

## Colour roles

| Role | Tokens | Use |
|---|---|---|
| Chrome | `--bg`, `--surface*`, `--border*`, `--text*`, `--nav-*` | UI surfaces and text |
| Accent | `--accent*`, `--glow*` | Active state, primary action, focus — not on map data or charts |
| Levels | `--level-*` | Heat-stress classes: NORMAL, MODERATE, HIGH, SEVERE, NO DATA, INDICATIVE |
| Status | `--success`, `--warning`, `--danger`, `--info` (+ `-soft`) | Jobs, forms, alerts — always with icon + text |
| Data ramps | `--heat-1…9`, `--cool-*`, `--green-*`, `--seal-*`, `--vuln-*` | Map layers, legends (theme-independent) |
| Diverging | `--dt-*`, `--ds-*`, `--div-mid` | Temperature change, sealing change |
| Bivariate | `--biv-11…33` | Heat × vulnerability |
| Uncertainty | `--unc-*` | Hatch (low confidence), dots (gap-filled), no data |
| Series | `--series-1…8` | Chart series in fixed order; max 3 in scatter plots |
| Measure types | `--measure-*` | Adaptation measure type (map outlines, icons, summary charts), fixed order, always with the type name; non-warm |

- Confidence is shown as a neutral 3-pip chip (■■■ / ■■□ / ■□□), never with level colours.
- `--text-faint` only for placeholders/disabled (fails 4.5:1).
